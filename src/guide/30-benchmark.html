Benchmark: tasks and scoring

Each track fixes the input, the output, the metric and the evaluation set. Three tracks have a kit that runs now; the robot track is run on the physical system. The results of current models follow the four tracks.

  1. Kit released

    Detection and instance segmentation

    Find every part in a top-down scanner image and give its class, box and mask.

    Input
    One scanner image, {{ det.frame_px }} × {{ det.frame_px }} pixels, taken after a step.
    Output
    Class, score, box and mask of each part, over {{ n.classes | num }} part classes. Masks are scored either as visible masks (a part in place but fully covered is an ignore region) or as complete (amodal) masks.
    Metric
    COCO AP averaged over IoU 0.50:0.95, for masks and boxes; also AP50, AP75, AP by size, AR, per-class AP and AP by occlusion. Mean AP is taken over the {{ det.classes_with_test | num }} classes that have test instances.
    Evaluation set
    The test split: {{ det.desktops.test | num }} desktops, {{ det.images.test | num }} images, {{ det.instances.test | num }} instances. Splits are by whole desktop (split and counts).
    Kit
    benchmarks/level1/: COCO split builder, scorer with a self-check, training and prediction scripts for a YOLO segmentation model and a Mask R-CNN.

    Run it: get started, evaluate

  2. Kit released

    Visual question answering

    Answer a question about a disassembly sequence from its images, as one JSON object.

    Input
    The images of a step from one or more cameras (two moments for questions about a change), with the parts in question outlined, and the question.
    Output
    A strict JSON answer in the task's format, e.g. a list of boxes, a state, a yes or no, or a removal plan.
    Metric
    Set per task: accuracy, exact match, F1, a box hit at IoU 0.5, or a replay of a plan on the relations (task table).
    Evaluation set
    eval_v3: {{ qa.eval | num }} questions over {{ n.qa_tasks | num }} tasks, drawn from all {{ n.desktops | num }} desktops; no desktop holds more than a fifth of a task. Each record also carries its desktop's train / test split in label.split.
    Kit
    vlm/vlmpack_2026-11-05/tools/: self-check, chat converter (OpenAI, Qwen-VL and InternVL formats), scorer with reference lines (chance, most frequent answer, question without its image).

    Run it: get started, evaluate

  3. Kit released

    Depth from a single image

    Predict depth from one scanner image; the scanner's own 3D measurement is the reference.

    Input
    One scanner image, {{ det.frame_px }} × {{ det.frame_px }} pixels.
    Output
    A depth map of that image, in metres. A model that gives depth up to a scale is scored after alignment only.
    Metric
    As predicted: MAE, RMSE, absolute relative error, the share of pixels within a ratio of 1.25, and the median scale (predicted over measured depth). After dividing each prediction by its scale: MAE, RMSE, absolute relative error and the share within 1.05.
    Evaluation set
    The first step (S01) of {{ res.depth.desktops | join(', ') }}. The reference comes from reconstructions/scanner/ and covers about half of the pixels of each picture; every desktop counts the same.
    Kit
    depth/ in the code repository: reference maps from the point clouds, and the scorer.

    Run it: get started, evaluate

  4. Data released

    Robot disassembly

    Remove the part named in an instruction and put it in the sorting zone, on the real robot.

    Input
    The instruction, and the images of the wrist and base cameras. Policies learn from {{ n.robot_demos | num }} demonstrations in two settings: parts on a fixture ({{ n.robot_fixtured | num }}) and parts on a motherboard ({{ n.robot_on_board | num }}).
    Output
    Arm and gripper actions for the whole trial.
    Metric
    Trials completed. A trial fails when it reaches 150 s or when the operator judges that the robot cannot finish.
    Evaluation
    On the system the demonstrations were recorded with (a UR5e arm with a Robotiq 2F-85 gripper), with the same instructions and home pose. Fixture: seven part categories, five fixture configurations each, ten trials per configuration ({{ res.robot.rows[0].trials | num }} trials). Motherboard: {{ res.robot.rows[2].trials | num }} trials.
    Data
    The demonstrations are in raw/robot/ (layout). The track has no offline kit: it is run on the physical system.

F1 pools matches, false positives and misses over classes and images at IoU 0.50, at a confidence threshold chosen on the validation split. Class mIoU averages over the {{ det.classes_with_test | num }} classes present in the test annotations; pixel IoU is total intersection over total union for all {{ n.classes | num }} classes. YOLO26m-seg, Mask R-CNN R50-FPN v2 and RF-DETR-Seg are trained end to end; DINOv3 + Mask R-CNN keeps the DINOv3 backbone frozen. SAM 3 takes the {{ n.classes | num }} class names as text prompts, before and after fine-tuning. The two frozen SAM rows take the boxes, labels and scores of RF-DETR-Seg and only draw the masks.
